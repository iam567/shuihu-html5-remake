## 重点入口

| 地址 | 静态观察 |
|---|---|
| 0x7A6 | 不终止的双分支更新循环，由 RAM 0xFFE116 是否为 0 选择分支。函数内明确列出每个分支的更新调用顺序。 |
| 0xE50 | 设置 VDP 控制命令，从 A2 逐字写入 VDP 数据端口，以 0x3402 作为终止标记。 |
| 0x1028、0x1060 | 两个矩形 tilemap 写入循环，依赖 D0/D1 坐标、D2/D3 的循环上界、A2 数据；每行地址推进 0x80 字节，命令基数分别 0x40000003 和 0x60000003。 |
| 0x17698 | 从 ROM 0x176EA 拷贝 20 × 16 = 320 字节到 RAM 0xFFE630，并初始化几个状态字段。 |
| 0x7622 | 从 ROM 0x7650 读取 16 组，每组 8 字节，写入起始于 RAM 0xFFE000、跨度 16 字节的槽位。 |
| 0x18274 | 从 ROM 0x1828C 拷贝 64 字节到 RAM 0xFFE2C0。 |

以上是操作观察；具体对象名称和 gameplay 语义必须结合调用点、数据和运行时验证。

## 质量边界

531 个候选函数都返回了伪代码，但不意味着 531 个都正确。50 个输出含警告注释，16 个含 `halt_baddata`，42 个位于 0x29400 及以后，可能含把资源当代码识别的结果。详细统计见 `quality.json`。不要把数量当完整源码恢复度。

函数名 `Seed_*` 是分析者给定地址的标签，`FUN_*` 是自动名称；都不是原始源码名称。寄存器调用约定没有完整恢复，`unaff_A2`、`in_D0` 等经常实际是参数。Ghidra 的默认 m68k 语言可解码 68040 超集；与 MD 实际 68000 有差异。RAM、IO、VDP 内存块是分析模型，0xFF0000 与符号扩展镜像 0xFFFF0000 暂建为独立块，未自动表达硬件别名关系。

REA raw-binary 的 `--entry-point 0x0` 同时设定载入基址和合成入口，不能填真实复位值 0x4BA，否则会错误移动 ROM。该 REA 测试不模拟复位向量。完整 Ghidra 项目通过 PrepareMegaDrive.java 明确添加真实入口。

全局 Codex 配置未修改。使用此引擎须为命令临时设置 JAVA_HOME 和 GHIDRA_INSTALL_DIR，值见 `run-analysis.sh`。该脚本用于首次导入；已有项目可直接继续分析，避免重复导入。
