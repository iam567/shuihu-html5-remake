## 已定位的系统

### 启动和硬件初始化

`0x0004BA` 读取 `0xA10001`，屏蔽低四位；非零时向 `0xA14000` 写入 `0x53454741`（SEGA）。随后屏蔽中断、设置 VDP、初始化三个手柄端口控制寄存器。

`0x000524–0x000534` 从 ROM `0x0293C4` 连续写入 19 个 VDP 寄存器字。`0x000538–0x000544` 从工作 RAM 基址连续清零 16,381 个长字，即 65,524 字节；不能笼统写成“清空全部 RAM”。随后配置 DMA 并等待忙状态结束。

启动还依次调用 `0x028046`、`0x1E3A00`、`0x0280D4`、`0x1E7618`，其中部分为 Z80/声音初始化。

### 帧驱动与主循环

Level 6 入口 `0x000104` 保存寄存器，调用 `0x1E4100`，递增 `0xFFE120`。当 `0xFF6000` 为零时置位它，递增 `0xFF6010`，并执行输入、调色板与其他更新。

`0x000E40` 明确执行：清零 `0xFF6000`，循环等待该字节变成非零，再返回。结合中断路径，可推断它是帧同步等待例程。没有运行证据，不能确定具体 PAL/NTSC 帧率或所有循环执行时长。

主循环选择点在 `0x0007A6`，按 `0xFFE116` 分两条路径：

- 非零路径从 `0x0007B2` 开始，帧等待后依次调用许多更新例程，`0x0008C6` 跳回选择点。
- 零路径从 `0x0008CC` 开始，调用另一组更新例程，`0x000974` 跳回选择点。

中断也根据 `0xFFE116` 的 0/1 值调用不同更新函数。**两条路径的游戏语义尚未证实**，不能直接命名为“大地图/战斗”或“单人/双人”。

### 手柄采样

`0x000478` 设置端口地址 `0xA10003` 和状态缓冲 `0xFF6003`，经 `0x00048C` 采样后将端口地址加 2，继续第二手柄。

采样代码切换端口输出的 0/0x40，组合两次读取、取反，存入 RAM，并计算新旧状态变化。这符合 MD 手柄扫描结构。`0xFF6003/04` 是第一个手柄状态/变化状态的候选入口；具体变化位的后续用途和每个键对应的游戏动作仍需跟踪。

### 图形布局与调色板

初始化表 `0x0293C4` 包含 `0x8230, 0x8338, 0x8407, 0x8578, 0x8C81, 0x8D3D, 0x9011`。按 VDP 寄存器定义解码，可得初始化时的候选 VRAM 布局：

| 内容 | 初始化基址 |
|---|---|
| Plane A | 0xC000 |
| Window | 0xE000 |
| Plane B | 0xE000 |
| Sprite attribute table | 0xF000 |
| Horizontal scroll table | 0xF400 |

Plane B/Window 共用地址是初始化表的观察，不代表两者在所有场景同时使用；后续会重设寄存器，例如启动再次使用 `0x028162` 的配置表。`0x8C81` 指向 H40 模式，但整个游戏的最终显示尺寸、模式切换和可见高度尚未运行验证。

`0x00018A` 在 `0xFF6001` 标志置位时，从 `0xFFEF80` 向颜色 RAM 上传调色板。`0x000E7C` 遍历 64 个颜色，分别以 `0xE00/0xE0/0xE` 掩码处理分量，逐步增加，再触发上传并等待帧；`0x000EF0` 是相应减暗路径。这为复刻淡入淡出效果提供了直接代码基础。

`0x000E50` 将图块编号转换为 VDP 写命令，从 A2 逐字写入数据端口，遇 `0x3402` 停止。可确认这个路径是带结束标记的数据传输，而不是据此断言所有图像都采用同一种压缩或格式。

可继续追踪的资源入口：`0x08196A`、`0x09FE38`、`0x0DAC96`、`0x0DC4C2`，以及调色板候选 `0x0292C4/0x029344`。这些是实际加载路径引用，尚未导出可识别画面。

### 音频

`0x1E3A00` 请求 Z80 总线，操作复位，从 `0x1E3B00` 读取长度，再把后续字节复制到 `0xA00000`，随后释放总线/复位。这是独立声音处理器驱动装载路径。

`0x1E41D4` 使用 `0xFF6D00` 并访问声音硬件相关寄存器，可作为声音命令入口候选；不能仅据此命名具体曲目。

`0x1E7618` 向 `0xC00011` 写入 `9F/BF/DF/FF/E7`，符合 PSG 初始化/静音操作。`0x1E7642` 通过 `0x1D84B6` 表和 `0xFF6F54` 一带状态选择音频相关数据。音频条目数、乐曲格式与音色尚未恢复。

### 疑似存档初始化

`0x027FB8` 分别从 `0x200001/03/05/07`、`0x202001/03/05/07`、`0x203001/03/05/07` 读取四个奇地址字节，拼为长字，与 `0x06090108` 比较。任一匹配即返回；全部不匹配时，从 `0x200001` 开始隔字节清零 8,192 个字节。

这种 ROM 尾部以外的奇地址访问、签名检查与初始化行为支持“SRAM/持久数据初始化”的推断。**还不能确认三个存档槽、存档结构、校验方式或补丁作者设置**；三个检查地址不等于三个槽位。

## 后续调查顺序

1. 配置支持 m68k raw-binary 的 Ghidra 引擎；ROM 映射基址为 0，并以向量表复位 PC 0x4BA 建立启动入口。REA CLI 的 entry-point 参数同时参与原始映射解释，不应随意把映射基址改成 0x4BA。
2. 用兼容 MD 模拟器观察用户这份 ROM 的启动/菜单，先备份独立存档目录；记录标题和两条主循环对应场景。
3. 分别做“新游戏 → 初始场景”“打开人物属性”“一场战斗”“存档/读档”的受控记录，逐项建立功能到地址的映射。
4. 导出图块、字库、调色板和地图，逐张核对，不把直接字节渲染的噪声视为有效资源。
5. 先恢复一个可验证的完整切片，再决定复刻平台：一张地图、一个角色、一个事件或一场战斗；数值与状态转换必须有原版对照。

建议复刻中独立实现状态、资源、输入和显示层。原版的 VDP/Z80 驱动细节用于解释行为；是否模拟这些硬件取决于最终平台。本轮尚未选择平台，也没有生成替代原版的游戏实现。
